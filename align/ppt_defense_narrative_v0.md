# 答辩叙事与 action-title spine v0

## 1. Defense thesis

委员会应该记住的一句话：

> 本毕业设计不是把大模型直接用于生成志愿建议，而是把高考志愿推荐重构为“确定性招生事实 + 多轮偏好澄清 + 可复查评测”的序贯决策系统，使系统能在不编造学校、专业、分数等事实的前提下，通过证据驱动的取舍问题识别用户隐藏底线。

更口语化的答辩版本：

> 我解决的是一个高风险推荐里的核心矛盾：事实不能让大模型编，偏好又不能只听用户第一句话；所以系统先用真实数据锁定事实，再通过多轮 A/B 取舍把用户没有说清的底线问出来。

## 2. Audience contract

答辩委员会大概率关心四件事，本次答辩按这个顺序回应：

| 委员关心 | 答辩回应策略 |
| --- | --- |
| 这个题目是不是只是套了一个大模型应用？ | 开场先定义高考志愿的“高风险、多目标、强事实约束、隐藏偏好”性质，说明问题不等于普通问答。 |
| 系统事实可靠吗？ | 前半段明确“LLM 不生成事实候选”，展示 PostgreSQL、专业树、学费字段、质量画像和地域树作为证据底座。 |
| 方法有没有实质机制，而不是 prompt 包装？ | 中段讲清非补偿性 SAVF、UCB 主动探测、帕累托候选对、Bradley-Terry 后验追踪如何组成闭环。 |
| 实验能否证明机制有效？ | 后半段用 180 条受控测试画像、参考基线横评和主消融实验说明完整系统的优势来自交互链路，而非单轮模型能力。 |

答辩风格：少讲“我用了很多模块”，多讲“每个模块解决哪个高风险决策问题”。每个技术点都回到同一个判断：事实可信，偏好可澄清，过程可复查。

叙事总览页策略：保留“数据 + Agent + Benchmark”作为一页显式总览，但它不是全篇唯一主线，而是一张支撑结构图。建议解释为：

- 数据：回答“事实从哪里来，为什么不让 LLM 编候选”。
- Agent / 决策模块：回答“系统怎样把用户没说清的底线问出来”。
- Benchmark / 受控测试：回答“怎么证明这个交互链路有效，而不是只靠单轮生成”。

## 3. Rubric / committee strategy

显式评价标准未知，因此采用本科毕业设计答辩的稳妥策略：

- 工程完整性：展示系统从数据证据层、推荐决策层、智能体服务层到前端交互和测试环境的闭环。
- 技术深度：重点解释为什么需要非补偿性建模、主动探测和后验更新，而不是只展示界面。
- 事实可信度：反复强调事实候选来自确定性证据层，LLM 的边界是语义归一、规划和表达。
- 实验可复查性：说明受控测试集、自动对弈日志、F1@N、MAE 和过程指标如何支撑结论。
- 自知边界：主动承认当前评测以模拟用户为主，跨省跨年份和真实用户研究仍是后续工作。

## 4. Argument arc

### 4.1 Situation

高考志愿填报不是普通推荐：它同时涉及分数、位次、选科、学费、地域、专业、风险等事实与偏好，错误建议的代价高。

开场可以用 20-30 秒现有方案对比进入问题：展示阳光高考、夸克高考等已有志愿填报方案或产品形态，说明它们可以帮助用户获得信息、检索条件或生成建议；但本设计要进一步回答的是“当用户第一句话并不完整时，系统怎样用真实证据把隐藏底线澄清出来”。具体功能点和页面截图应在 storyboard 或 asset/layout 阶段再基于公开页面或本地素材核验，不在 narrative 阶段新增未经确认的产品事实。

### 4.2 Gap / problem

传统静态 RAG 或一次性检索能增强事实，但很难解决两个问题：

- 用户第一轮表达常不完整，显式约束不等于真实偏好。
- 大模型直接生成事实候选有风险，尤其是学校、专业、分数、位次和学费。

### 4.3 Approach

系统采用“先锁事实、再问取舍、后给推荐”的结构：

1. 约束解析和 PostgreSQL / 标准化证据层先限定事实可行域。
2. 非补偿性 SAVF 防止预算、专业等底线被高分维度线性抵消。
3. UCB 主动选择最值得澄清的偏好维度。
4. 帕累托候选对把“放宽什么、换来什么”变成用户能回答的 A/B 取舍。
5. Bradley-Terry 后验和不确定性膨胀机制把反馈写入偏好状态。

### 4.4 Evidence

实验先比较完整系统与静态检索提示，再比较去除主动探测和去除后验追踪的内部消融。核心证据不是单个漂亮案例，而是：

- 180 条受控测试画像。
- 五个基座模型上的参考基线横评。
- 固定模型下的主消融。
- 过程指标对探测方向、权衡张力和后验状态的解释。

### 4.5 Contribution

本设计的贡献应讲成五点：

1. 定义冰山式偏好问题，把高风险推荐从“回答是否流畅”推进到“能否发现隐藏底线”。
2. 构建可审计数据证据层，让学校、专业、分数、位次和学费不由 LLM 自由生成。
3. 实现事实约束下的偏好澄清决策模块。
4. 用运行时状态机组织可回放的交互链路。
5. 构建受控测试集和消融实验，使机制贡献可复查。

### 4.6 Limitation / answer

不要把系统说满。结尾主动承认：

- 当前主要用模拟用户和受控测试集验证机制差异。
- 跨省份、跨年份泛化需要额外验证。
- 主动澄清有引导性，真实产品中需要用户控制机制。
- 生活成本、家庭照护距离、转专业政策、保研机会等复杂因素还未完全进入证据层。

## 5. Emphasis map

### Must-say

- 高考志愿推荐是高风险决策，不是普通聊天问答。
- 开场可用阳光高考、夸克高考等现有方案展示作为问题引入，但只作为场景对比，不作为实验基线。
- 用户显式话语不等于完整偏好，隐藏底线需要被澄清。
- LLM 不生成事实候选，事实来自 PostgreSQL 和标准化证据层。
- 非补偿性 SAVF 解决线性补偿陷阱。
- UCB + 帕累托候选对 + Bradley-Terry 后验构成多轮偏好澄清闭环。
- 实验用 180 条受控测试画像和消融验证完整链路贡献。
- 局限性要主动讲，不把系统包装成生产级升学顾问。
- “数据 + Agent + Benchmark”保留为显式总览页，用来解释系统支撑结构。

### Can-compress

- 专业树和地域树的全部构建细节。
- 静态混合检索基线的 embedding、reranker、pgvector 细节。
- 公式推导细节。
- 前端页面的每个控件。
- 过程指标的所有数值。

### Backup-only

- 专业树覆盖 v2 的来源分布、clean validation、Hit@10、错分聚类。
- 地域树 414 个省-市对、3,219 所学校覆盖细节。
- `major_geo_v1`、`risk_band_v1`、`multi_axis_v2`、`v1_hybrid_rag` 等旧口径实验。
- Python 作图代码、数据文件路径、复现命令。
- 终稿一致性报告与当前 LaTeX 结构差异。

### Omit

- 与终稿不一致的旧七章结构。
- 任何未被终稿或 confirmed fact ledger 支撑的新指标。
- “完全自治多智能体”“全自动升学决策”“专业树全部人工正确”等过度说法。
- 项目目录中的历史 PDF、临时图、未被终稿引用的旧素材。

| 为什么不用线性加权推荐？ | 方法必要性 | SAVF 页 | 高考志愿中预算、专业底线等有非补偿性，不能被学校层次等高分维度抵消。 |

| 指标提升幅度是否足够？ | 实验说服力 | 实验结果页 | 高风险推荐更重视头部候选和偏好边界可信度；完整系统的价值是把事实、取舍、反馈和状态连成可复查机制。 |
| 专业树全量覆盖是否代表全对？ | 数据过度声明 | 数据证据层页或备份 | 全量覆盖是可审计挂载覆盖，不等于全部语义边界人工正确。 |
| 地域层级能否代表就业机会？ | 不当因果 | 数据证据层页或备份 | 地域树提供地理/城市层级证据，不编码就业机会、生活成本或城市收益。 |

## 7. Action-title spine

说明：以下是论证骨架，不是 storyboard。标题必须能单独串成答辩故事；具体页数、版式、图表和讲稿在后续阶段再定。

### Opening and framing

1. 大模型驱动的高考志愿推荐系统必须同时守住事实可信和偏好真实两条线。
2. 现有志愿填报方案能帮助用户获得信息和建议，但隐藏底线仍需要被证据化澄清。
3. 高考志愿填报的难点不是“回答问题”，而是从不完整表达中发现真实底线。
4. 本设计把一次性推荐改造成事实约束下的多轮偏好澄清系统。

### Problem and gap

5. 静态检索能找到事实，却难以判断用户愿意为哪类收益放宽哪条约束。
6. 直接让大模型生成候选会破坏高风险决策中最重要的事实边界。

### Approach

7. 数据、Agent 和 Benchmark 分别支撑事实可信、偏好澄清和机制验证。
8. 系统先用结构化证据层锁定事实可行域，再让大模型负责表达和规划。
9. 非补偿性价值映射防止预算、专业等底线被线性总分掩盖。
10. UCB 主动探测让系统优先询问最有诊断价值的偏好维度。
11. 帕累托 A/B 候选把抽象偏好变成用户能够回答的具体取舍。
12. Bradley-Terry 后验把用户反馈写入可延续的偏好状态。

### System implementation

13. 运行时状态机把语义归一、约束解析、证据探针、反馈更新和终局推荐串成可回放链路。
14. 前端交互把系统内部的偏好澄清过程呈现为可理解的取舍问题和推荐报告。

### Evidence

15. 受控测试集用隐藏底线用户画像检验系统是否真的恢复真实偏好。
16. 参考基线横评显示，完整系统的优势主要来自交互式证据链路，而不是更强的单轮生成。
17. 主消融实验显示，主动探测和后验追踪分别支撑探测方向选择与反馈吸收。
18. 过程指标进一步说明，完整系统更能形成有张力的问题并稳定更新偏好状态。

### Contribution and close

19. 本设计的贡献是把事实证据、主动澄清、在线后验和可复查评测组织成一个工程闭环。
20. 系统仍需真实用户研究和跨省跨年份泛化验证，但已经证明了高风险推荐中“先问清底线再推荐”的技术路径。

## 8. Ghost deck test

只读 action-title spine，可以形成完整论证：

- 前 4 句定义题目价值：从现有方案和高风险场景切入，说明问题不是普通大模型问答，而是事实与偏好双约束。
- 第 5-6 句指出现有路线不足：静态检索和直接生成各有缺口。
- 第 7-12 句给出支撑结构和方法闭环：数据、Agent、Benchmark 总览之后，再展开事实层、非补偿性、主动探测、帕累托取舍、后验更新。
- 第 13-14 句证明工程实现：状态机和前端交互使链路可运行、可回放。
- 第 15-18 句给出证据：受控测试、基线横评、消融和过程指标。
- 第 19-20 句收束贡献和边界：系统完成了可审计偏好澄清闭环，但仍保留真实用户和泛化限制。

结论：标题链条能独立讲清“为什么做、怎么做、怎么证明、边界在哪”。后续 storyboard 应保留这个顺序，不按论文章节机械搬运。

## 9. Storyboard handoff notes

- 15 分钟纯讲建议总页数约 19-22 页，其中内容页约 15 页，封面/目录/过渡/致谢不计入内容页。
- 主线应采用“问题 -> 约束 -> 方法闭环 -> 系统实现 -> 实验证据 -> 贡献边界”的答辩顺序，而不是严格照搬论文 5 个章节。
- 开场例子采用“现有方案展示与分析”：可用阳光高考、夸克高考等作为场景入口，控制在 20-30 秒；具体产品功能、截图或页面文字需要在 storyboard/asset 阶段补充来源核验，不作为论文实验基线。
- 方法部分不要超过 5 页，否则实验和贡献会被压缩。
- 数据证据层最好作为“事实可信”论据服务于主线，不单独展开成大量数据治理页。
- 旧三贡献口径保留为一页显式总览，并转化为支撑结构：数据负责事实可信，Agent/决策模块负责偏好澄清，Benchmark/受控测试负责机制验证。
- 封面不放英文副标题；英文题名只作为材料元数据或必要时备份页说明。
- 备份页必须覆盖：LLM 事实边界、专业树全量覆盖含义、地域树边界、UCB 非严格最优、模拟用户局限、旧口径实验边界。
- 后续 storyboard 阶段不要新增事实；需要新增数值时先回 fact ledger 修订并确认。
