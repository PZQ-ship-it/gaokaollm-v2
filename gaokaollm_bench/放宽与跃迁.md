# 动态放宽与 Pareto 跃迁实验总览

本文档用于整理当前 v2 项目中“动态约束放宽与 Pareto 跃迁”的论文主线。它不新增实验结论，只把已有数据层、Agent、Benchmark、PostgreSQL 快照和离线评测结果收束成可直接写入毕业设计论文的方法与实验材料。

当前论文贡献采用“数据 + Agent + Benchmark”三贡献结构：

- **数据贡献**：用 PostgreSQL 招生快照、分数/位次、学费、专业树、专业质量标准化层和就业结果标准化层，提供可核验的动态决策证据。
- **Agent 贡献**：用 LangGraph `gatekeeper -> radar -> negotiator` 架构，在真实招生数据库约束下进行证据驱动 Pareto 谈判，而不是只迎合用户初始硬约束，也不是凭空劝说用户改变偏好。
- **Benchmark 贡献**：用冰山画像、多轮沙盒和事实/过程联合评价，评测高考志愿 Agent 是否能发现用户显性红线背后的可妥协空间。

## 1. 研究定位

高考志愿咨询中的用户偏好往往不是一次性完整表达的。用户可能先说“只想留在浙江”“只想读临床医学”“只求稳妥不要冲”“学费别太贵”“希望以后就业和薪资稳定”，但这些显性红线背后可能存在隐性可妥协条件：如果系统能给出真实学校、专业、最低分、位次、风险层级、学费、专业质量或就业结果证据，用户可能愿意接受部分放宽。

因此，本项目把任务定义为：

> 在真实 PostgreSQL 招生数据约束下，发现约束放宽后的可达志愿集合，并通过多轮对话验证 Agent 是否能触发用户接受更优或更完整的 Pareto 方案。

这里的“跃迁”不只指学校层次提升，也包括志愿组合质量、预算性价比、专业质量和就业结果证据提升。例如，`major_geo_relax` 关注专业与地域联合放宽后的学校层次收益；`risk_band_relax` 关注从单一保守方案扩展为 `chong/wen/bao` 冲稳保组合后的组合完整性收益；`tuition_value_relax` 关注小幅超预算换取更好可达方案；`major_quality_relax` 和 `employment_outcome_relax` 则把数据补充转化为专业质量与就业结果证据。

## 2. 已实现能力矩阵

| 放宽能力 | Benchmark 画像 | Agent 探测 | 主要证据 | 当前状态 |
|---|---|---|---|---|
| `province` | 显性坚持本省，隐藏可接受省外高层次学校 | `geo_relax` | 学校、省份、专业、最低分、tier | 已实现，作为 `major_geo_relax` 的组成部分 |
| `major` | 显性坚持原专业，隐藏可接受相近或替代专业 | `major_relax` | 专业树阶段、学校、专业、最低分、tier | 已实现，作为 `major_geo_relax` 的组成部分 |
| `major_geo_relax` | 显性专业/地域红线，隐藏可接受联合放宽 | `major_geo_relax` | 专业树层级、跨省候选、最低分、tier | 已实现并完成主实验 |
| `risk_band_relax` | 显性只求稳，隐藏可接受冲稳保组合 | `risk_band_relax` | `score_margin`、`rank_gap`、`chong/wen/bao` | 已实现并完成主实验 |
| `strength_relax` | 显性看重学科实力，隐藏可接受跨省实力跃迁 | `strength_relax` | `major_strength_rank`、评级、最低分、最低位次 | 已实现并完成扩展实验 |

| `major_quality_relax` | 显性坚持目标专业，隐藏可接受更强学校-专业证据 | `major_quality_relax` | `school_major_quality_profiles`、`quality_score`、专业排名/学科评估/特色/重点/满意度 | 已实现并完成扩展实验 |

这些能力都遵守同一边界：被测 Agent 只使用用户显式话语抽取出的分数、省份、专业、选科、预算、风险偏好、质量偏好、就业导向等约束，以及 PostgreSQL 查询结果；它不读取 benchmark persona 的 `implicit_flexibilities` 或 `volunteer_set`。

## 3. Agent 架构

业务 Agent 使用 LangGraph 组织为：

```text
gatekeeper -> radar -> negotiator
```

| 节点 | 职责 | 输出 |
|---|---|---|
| `gatekeeper` | 从用户话语中抽取分数、省份、专业、预算、选科、风险偏好、质量偏好和就业导向，并查询当前硬约束 baseline | `constraints`、`baseline_results`、`score_waste` |
| `radar` | 调用确定性 SQL 探针，寻找可谈判的 Pareto 机会 | `major_geo_relax`、`risk_band_relax`、`strength_relax`、`tuition_value_relax`、`major_quality_relax`、`employment_outcome_relax` |
| `negotiator` | 把真实候选组织为可解释回复，要求包含学校、专业、最低分、位次、风险、学费、质量或就业证据 | 面向用户的谈判回复 |

`hard_constraint` baseline 只报告当前显性硬约束下的可达志愿，不主动产生上述 Pareto opportunities。因此它代表“迎合显性红线”的保守系统，用来和证据驱动谈判 Agent 做对照。

## 4. Benchmark 架构

Benchmark 使用“冰山画像”建模用户：

- `explicit_red_lines`：用户开场会明确说出的偏好或红线。
- `implicit_flexibilities`：只有看到足够证据后才可能接受的隐藏妥协条件。
- `volunteer_set`：由真实 PostgreSQL 数据或标准化证据层生成的隐藏目标志愿集合，用于评测，不暴露给 Agent。

评测流程为：真实 DB gap 发现 -> persona 生成 -> 多轮沙盒对话 -> transcript 持久化 -> deterministic factual judge 与 process judge 汇总。输出包括 transcript、逐例 report、summary 和论文摘要。

事实评价关注是否虚构学校或分数；过程评价关注是否触发隐藏妥协。这样可以区分“事实正确但不谈判”的 baseline 与“事实正确且能触发妥协”的 Pareto Agent。

## 5. 核心算法与数据证据

### 5.1 `major_geo_relax`

`major_geo_relax` 用于处理“专业 + 地域”联合放宽。它保留分数、预算、选科等事实硬约束，去掉省份限制，并按专业树逐级放宽原专业约束。

专业放宽顺序采用 staged relaxation：同叶子或近邻专业、同父类或相关大类、probe 邻居大类，必要时退化到 `any_major`。候选过滤与 persona 生成保持一致：本科、学校质量过滤、特殊专业过滤、同校数量上限、去重、优先最新年份，并按 tier、ranking、min_score 排序。

### 5.2 `risk_band_relax`

`risk_band_relax` 用于处理“只求稳 / 保守 / 不要冲”的风险偏好放宽。它不改变省份、专业、选科、预算等硬约束，只把单一保守方案扩展为冲稳保组合。

风险层级优先使用 `rank_gap = min_rank - student_rank`，位次数据缺失时退化到 `score_margin = score - min_score`。每个候选保留学校、城市、省份、专业、最低分、最低位次、分差、位次差、风险层级和学校 tier/ranking。

### 5.3 `strength_relax`

`strength_relax` 用于处理“更看重学科实力 / 专业排名 / 重点学科”的实力偏好放宽。它以当前省份、分数和专业约束下的可达志愿作为锚点，再在全国范围内寻找同专业或相近专业中学科/专业排名更强、且仍满足分数、选科和预算约束的可达候选。

候选输出保留学校、城市、省份、专业、最低分、最低位次、`major_strength_rank`、`major_strength_rating`、学校 tier/ranking 等字段。该能力属于扩展实验，证明学校/学科实力证据可以接入同一评测闭环。

### 5.4 `tuition_value_relax`

`tuition_value_relax` 用于处理学费预算红线。它保留分数、专业、选科等硬约束，只在学费上限附近做小幅放宽，候选必须给出学费、学费增量、最低分和学校 tier/ranking 收益。

这一能力使用 `admission_plans.tuition` 作为核心数据证据。它的意义不是鼓励用户盲目提高预算，而是把“小幅超预算是否值得”变成可核验、可对照的 Pareto 谈判问题。

### 5.5 `major_quality_relax`

`major_quality_relax` 用于处理专业质量证据增强。它使用 `school_major_quality_profiles`，将专业排名、学科评估、特色专业、重点专业、满意度等来源统一成 `quality_score`、`quality_gain` 和 `evidence_sources`。

这一能力让 Agent 可以说清楚“同样或相近专业中，这所学校为什么在专业质量上更有证据”，而不是泛泛地说“学校更好”。

### 5.6 `employment_outcome_relax`

`employment_outcome_relax` 用于处理就业导向放宽。它使用 `major_employment_outcome_profiles`，将专业就业画像中的就业排名、热门就业城市、行业分布、岗位分布、薪资分布和 `outcome_score` 转化为可谈判证据。

这一能力保留分数、选科、预算等硬约束，允许在同专业或专业树近邻专业中寻找就业结果证据更强的候选。候选必须给出学校、专业、最低分、最低位次、`outcome_score`、`outcome_gain`、`employment_rank`、`top_industry` 和薪资分布等证据。

## 6. 实验结果

六组实验的核心指标如下。斜杠格式依次为：

```text
elicitation_success_rate / mean_pareto_gain / mean_hallucination_rate / avg_turns
```

| 实验 | 类型 | `app_pareto` | `hard_constraint` | 结论 |
|---|---|---:|---:|---|
| `major_geo_v1` | 主实验 | `0.900 / 0.900 / 0.000 / 5.20` | `0.000 / 0.000 / 0.000 / 7.00` | Agent 能用联合放宽证据触发 9/10 个隐性妥协 |
| `risk_band_v1` | 主实验 | `1.000 / 3.000 / 0.000 / 5.00` | `0.000 / 0.000 / 0.000 / 15.00` | Agent 能把单一保守偏好扩展为冲稳保组合 |
| `school_strength_v1` | 扩展实验 | `1.000 / 15.000 / 0.000 / 5.00` | `0.000 / 0.000 / 0.000 / 11.00` | 学校/学科实力证据可接入同一谈判闭环 |
| `tuition_value_v1` | 扩展实验 | `1.000 / 1.000 / 0.000 / 5.00` | `0.000 / 0.000 / 0.000 / 11.00` | `admission_plans.tuition` 可支撑小幅超预算换收益的谈判 |
| `major_quality_v1` | 扩展实验 | `1.000 / 16.000 / 0.000 / 5.00` | `0.000 / 0.000 / 0.050 / 11.00` | `school_major_quality_profiles` 可支撑专业质量跃迁证据 |
| `employment_outcome_v1` | 扩展实验 | `1.000 / 49.000 / 0.000 / 3.00` | `0.000 / 0.000 / 0.000 / 11.00` | `major_employment_outcome_profiles` 可支撑就业排名、行业、岗位和薪资证据谈判 |

主实验 `major_geo_v1 + risk_band_v1` 支撑论文的核心 Agent 与 Benchmark 贡献。四组扩展实验支撑数据贡献和框架可扩展性，说明同一套数据-探测-沙盒-评价流程可以接入学科实力、学费预算、专业质量和就业结果等更多真实证据维度。

需要保留失败样本：`major_geo_v1` 的唯一失败样本为 `real-db-set-浙江-569-009`。该样本说明当前 Agent 在某些 case 中会停留在较近的专业放宽阶段，未命中 persona 要求的更远 `any_major` 集合。论文中不应把 `major_geo_v1` 写成 100% 成功。

## 7. 论文解释口径

论文中可以把当前结果解释为：

> 本研究的核心贡献不是穷尽所有高考志愿偏好，而是提出一条可扩展的验证流程：先判断某个偏好是否能由真实数据库形成可核验 gap，再生成冰山画像，最后通过多轮沙盒和事实/过程联合评价验证 Agent 是否能触发 Pareto 妥协。当前系统已在专业地域、风险组合、学费预算、专业质量和就业结果等维度完成闭环，说明该框架可以从单一 Agent 策略扩展为数据驱动的动态决策评测体系。

这也解释了为什么需要同时报告 hallucination 与 elicitation success：一个系统可能事实正确但完全不谈判，例如 `hard_constraint`；论文关注的是在保持事实正确的同时，Agent 是否能发现并表达可接受的放宽收益。

## 8. 尚未实现或需谨慎推进的方向

以下方向仍作为后续工作，不作为当前论文第一版主贡献：

- 多年稳定性风险增强：利用多年份 `admission_scores` 估计分数和位次波动，增强 `risk_band_relax` 的风险证据。
- 城市收益指标：不能只凭 `schools.city` 写成“城市跃迁”，需要引入可核验的就业机会、生活成本或产业匹配证据。
- 专业就业城市匹配：可作为 `employment_outcome_relax` 的二期增强，但需要先统一就业城市、学校城市和行业机会的口径。
- 真实用户校准：用真实咨询或人工标注校准模拟用户的信任、犹豫、反问和接受阈值。
- 概率化录取风险模型：从当前确定性 `score_margin` / `rank_gap` 分层扩展为概率型录取风险估计。
- 家庭距离、校园文化、个人兴趣匹配：当前缺少稳定、可核验的 PostgreSQL 证据，适合写入展望而不是当前 benchmark 闭环。

这里的底线是：如果某个因素不能在 transcript 中落成“学校/专业/分数/位次/学费/质量/就业”等具体证据，就不应进入当前论文主实验。
